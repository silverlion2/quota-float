## Confirmed baseline defects

1. **Speculation changes personal spending guidance.** The previous pace implementation converted a public 48-hour probability into a midpoint and probability-weighted reset horizon, then persisted it in a daily baseline. The probability has no demonstrated calibration or independence across sources, and the predicted horizon can outlive the observation that created it. A user can be encouraged to spend quota before their provider-reported reset.
2. **Compact reset dates ignore local time.** `formatResetDate` extracted the ISO month/day before parsing the timestamp. The same instant represented as `2026-07-10T00:30:00Z` and `2026-07-09T17:30:00-07:00` produced different dates. Timestamp formatting now uses the local timezone, consistent with detailed dates/countdowns; calendar-only values retain their explicit calendar day. Six formatting tests pass, including this regression and invalid timestamp handling.
3. **Public-source failure isolation is incomplete.** One overall timeout around a joined request group discards already-completed source results when another request stalls. The native aggregation also reports the newest participating timestamp, potentially masking an older contributor's expiry.
4. **Reported announcement and source agreement overstate certainty.** A third-party flag is not independent verification of an official reset, and agreement between public trackers does not establish forecast accuracy. UI language and planning need to preserve this distinction.
5. **Manual refresh is swallowed by an automatic pass.** Single-flight returned the active automatic promise even for a forced user request. A bounded queued forced pass preserves manual intent while still avoiding concurrent refreshes.
6. **Credit-only snapshots lose last-known-good recovery.** Frontend merging recognized percentage windows and balances but omitted reset-credit-only snapshots. Transient failures then cleared a metric the native snapshot contract accepts.
7. **Diagnostic export includes unnecessary local text.** The clipboard report serialized the native diagnostic object and recent events wholesale, including a configuration directory and free-form event text. An explicit report projection is needed alongside the native redaction boundary.
8. **Release upgrade checks cover only installed versions.** The previous Windows script installed the old and candidate packages and compared versions, without launching or recovering them. The updated script additionally checks candidate launch, rollback launch, candidate reinstall/launch, and uninstall on an ephemeral GitHub-hosted runner, before draft publication. Local machines and self-hosted runners are explicitly rejected. Static syntax and 21 targeted formatting/release tests passed; real lifecycle execution is deferred to the release workflow.
