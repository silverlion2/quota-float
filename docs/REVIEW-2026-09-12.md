# 2026-09-12 产品完整性、交互性能与设计验收

## 本轮范围

本轮沿用本地优先的七平台额度监控定位，集中完成已有功能的交互闭环、异步稳定性与视觉一致性。没有增加账户写入、凭据上传或新的后台服务。三个低成本 Sub-Agent 分别检查应用生命周期、功能异常状态、历史图表性能，主任务负责整合审查、视觉、原生测试与发布。

## 设计与动效

- 动效统一为 120ms 控件/收起、160ms 弹窗/窗口入场、200ms 进度变化；原来的进度变化为 520ms。
- 移除窗口裁切路径、背景模糊及大阴影的逐帧动画，减少重复入场；动画结束恢复 `transform: none`。
- 弹窗共享不透明语义主题底色、16px 圆角、单一边框。保留主额度窗口的 Aurora、Graphite、Paper 与浅深色外观。
- 设置标签与表单值分别使用 10px 和 11px；布局说明可换行；窄视口的设置导航正确横向排列。
- 原生测试发现关闭弹窗时同步恢复焦点早于后台 `inert` 移除；改为提交完成后恢复，并覆盖替换弹窗不能被旧弹窗抢焦点的回归。
- 改善选中态、开关焦点、中文关闭按钮与系统操作反馈。
- 650ms Bar/Bottleneck 悬停保护保留；系统减少动态效果偏好继续生效。

长期规范见 [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)。这些是具体实现与验收项，并非对任何硬件的帧率或商业成熟度保证。

## 依赖与分发边界

`js-yaml` 间接开发依赖从 4.3.1 更新为 4.3.2，修复 [GHSA-2883-xcg3-v3hh](https://github.com/advisories/GHSA-2883-xcg3-v3hh)。正式依赖扫描 `npm audit --omit=dev --registry=https://registry.npmjs.org` 为零漏洞。

完整开发依赖仍有两项 moderate 报告，来自 Vitest/@vitest/mocker 的同一 [开发服务器路径读取公告](https://github.com/advisories/GHSA-82fw-gwwq-j7x9)。本项目测试使用 `vitest run` 与 jsdom，这些依赖不进入应用运行包；修复涉及测试框架主版本升级，应作为独立工具链升级验证，不能用 `audit fix --force` 混入此次桌面修正。

发布通过仓库现有 Release workflow 完成 Windows/macOS 打包、Tauri 更新签名、Windows Defender 扫描，以及草稿候选安装、升级、回滚、重装和卸载检查。公开结果以 [GitHub Releases](https://github.com/silverlion2/quota-float/releases) 与对应工作流为准，本地测试通过不等于已经公开发布。

Windows Authenticode、macOS Developer ID 和 notarization 与 Tauri updater 签名是不同边界。本轮不新增证书或修改信任配置。真实 Mac 的窗口视觉、多显示器和不同 DPI 仍需对应硬件验收，CI Universal 编译不能替代这些测试。
