## Defects exposed and corrected

Creating a detached WebView from synchronous `open_focus_panel` deadlocked the Windows process. The command now runs asynchronously, consistent with [Tauri's documented Windows restriction](https://docs.rs/tauri/latest/x86_64-pc-windows-msvc/tauri/webview/struct.WebviewWindowBuilder.html). The creation/render/close scenario now passes against the rebuilt binary.

The test fixture now resets only its own application preferences, keeps the widget expanded while the native pointer is elsewhere, pins Codex, and reloads before assertions. It obtains a new element reference after reopening the control center. Failure screenshots are confined to the synthetic test WebView.

## Limits

The restricted execution environment initially prevented driver downloading and caused WebView script timeouts. The successful run used the approved unrestricted local test execution. The service still emits a non-fatal external-driver diagnostic and a teardown mock-store warning in embedded mode; all five native assertions and the runner exit code passed.

This is a native functional smoke test. It does not establish multi-monitor/DPI visual acceptance, macOS behavior, install/update/rollback, signing, startup latency, or whole-application CPU/memory budgets. The production frontend was rebuilt after the test; the test executable remains an isolated E2E artifact and is not a release package.
