# 数据解释与恢复更新

本轮基于 v0.3.30 深入检查额度连续性、费用完整性和刷新恢复。没有新增凭证来源，也没有修改平台账号或额度。

## 依据与复现场景

- 套餐在同一个重置时间下从 PLUS 90% 变为 PRO 40%，旧累计逻辑会记录 50 个百分点消耗。新逻辑只在可比较的同周期、同已知套餐边界内累计；历史重算使用相同规则。未知旧样本保留兼容，但不能消除已知的套餐变化边界。
- 模型缺少价格时，旧费用汇总内部保留已知价格小计 0，部分界面会将它呈现为完整费用 $0 和正常预算。本轮将完整估算、已知费用小计、未定价及无记录分别表达，价格不完整时不生成完整月预测或成本环比。
- 刷新失败会保留成功快照的 updatedAt；健康页此前却把它标为最近检查。现在检查时间与额度数据时间分开，首次失败不显示伪成功时间，进行中状态按平台显示。
- 网络恢复时仅重新检查失败且未暂停的来源，等待现有请求结束后再次判断；短时间连续联网事件合并。系统时间回拨视为检查已到期，避免一次性计时器空返回后停止轮询。
- 更新开发工具依赖 serialize-javascript 至 7.1.4、undici 至 6.29.1 / 7.30.1；重新安装后核对实际包版本，官方 npm audit 返回 0 个漏洞。

外部参考在 2026-10-25 读取：CodexBar 的 [Claude 数据语义](https://github.com/steipete/CodexBar/blob/main/docs/claude.md)明确保留未知模型用量、单独呈现已定价小计，并保留失败前采集时间；[UI 说明](https://github.com/steipete/CodexBar/blob/main/docs/ui.md)区分零值、不可用和不完整数据。本项目采用这些数据解释原则，未复制凭据发现或账号存储实现。

## 兼容性与限制

- 运行期检查时间和进行中状态不写入持久化 schema；额度读取仍留在 Rust 内且只读。
- 周/月摘要 JSON 升为 schemaVersion 2：价格不完整时完整费用为 null，已知小计单独命名。原明细 CSV/JSON 保持既有 nullable 金额协议。
- 已保存的旧日累计不自动扣减：压缩后的历史可能无法证明误计金额，不能为修复而猜测。保留的原始历史重算会使用新边界。
- 没有账号标识时无法识别同名套餐下的账号切换，也不能恢复已经压缩丢失的边界。
- API 等价估算不等于订阅账单。自动化合成数据不证明所有真实账号服务可用；macOS CI 构建不替代真实 Mac 视觉验收。
