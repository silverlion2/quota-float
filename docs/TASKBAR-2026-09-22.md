# Windows taskbar mode and edge expansion

## User-visible behavior

The Windows control center adds **Taskbar** beside Float, Ring, Bar and Bottleneck. This uses the existing native notification-area icon: a quota number lives inside the Windows taskbar, and clicking it opens the full detail panel. Collapsing the panel leaves no desktop widget. Choose another compact layout to return to a floating widget. Settings and saved layouts retain the choice.

The indicator represents the active provider's tightest remaining percentage window. Unknown, paused, unavailable and stale states must remain distinguishable; a missing value must never become zero. Credentials and provider access remain read-only inside Rust. The frontend requests an indicator refresh by provider ID; it does not pass credential or raw provider data to the tray.

Windows controls notification-area overflow. If the icon is hidden, the user can drag it out of the overflow area or enable it in taskbar settings. This release does not install an Explorer extension or force Windows visibility preferences. Taskbar mode is Windows-only; unsupported platforms retain the ordinary widget.

## Edge expansion defect

Native window resizing/repositioning can generate a transient mouse-leave event before the expansion IPC promise resolves. Previously that leave invalidated the expansion completion callback, leaving the compact React content inside an enlarged native window until a pending collapse fired. Re-entry during the same request could also enqueue duplicate expansions.

The corrected transition keeps native expansion completion separate from hover cancellation, deduplicates in-flight expansion and handles a genuinely committed collapse. Failed expansion must keep the compact launcher usable for retry. Regression tests exercise deferred native responses and rapid pointer transitions.

## Integration research

The supported implementation reuses Tauri's tray API rather than adding a dependency or embedding WebView2 in Explorer:

- [Microsoft notification-area guidance](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area): native status icons and associated popup interaction.
- [Tauri tray icon API](https://docs.rs/tauri/latest/tauri/tray/struct.TrayIcon.html) and [click event rectangles](https://docs.rs/tauri/latest/tauri/tray/enum.TrayIconEvent.html): dynamic icons and flyout positioning.
- [Windows taskbar extensions](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar-extensions): notification visibility remains under user control.
- [TrafficMonitor's taskbar implementation](https://github.com/zhongyang219/TrafficMonitor/blob/188b8773b959733bfc0e4f506c762d9a255883d4/TrafficMonitor/TaskBarDlg.cpp#L937-L959) uses window reparenting. That is unnecessary for the chosen notification-area mode and brings [cross-process DPI constraints](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent).

## Validation and rollback

Local validation: 416 frontend tests pass; 122 Rust tests pass, with the existing opt-in live Codex Profile test ignored. Production build, the original bundle budgets, version consistency, formatting, cargo check, strict Clippy and diff checks pass. Total production JavaScript gzip is 184,144 bytes against the unchanged 184,320-byte limit; repeated transition helpers and small native bridge chunks were consolidated without adding dependencies.

Windows native E2E passes all 12 scenarios, including three taskbar-open/Escape-hide cycles, viewport sizing and returning to Float. The test sends the real native event through the embedded test bridge and checks native window visibility; it does not simulate a physical taskbar click. The existing non-fatal external-driver diagnostic and mock-store teardown warning remain, with exit code zero. A first attempt failed in the test harness's event helper; using Tauri's native event command corrected the harness without changing application behavior.

Release evidence is recorded separately after the exact artifacts are published and verified. Automated geometry and synthetic native tests do not prove every physical monitor/DPI/Explorer-restart combination; real macOS interaction remains outside Windows validation. The flyout targets the requested bottom taskbar, rather than claiming support for custom top/side taskbar shells.

For presentation rollback, select Float/Ring/Bar/Bottleneck in the control center. For application rollback, use the previous public installer and the existing recovery-point workflow. Updater signatures are separate from Windows Authenticode and macOS notarization.
