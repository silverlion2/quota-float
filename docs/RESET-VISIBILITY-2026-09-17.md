# 重置预测可见性与整体质量审查 — 2026-09-17

## 问题与修复

用户反馈重置预测消失，并明确要求使用子代理检查整体质量。两个只读子代理分别检查预测链路和整体产品质量，主任务负责全部写入与验证。

代码确认了三条可复现路径：所有公开来源暂时失败时，前端用 `null` 清空仍然有效的结果；账号状态非 `ok` 时，独立公共信号跟着消失；已排除来源的数据时间仍参与合并结果的过期判断，导致两个新鲜有效来源被一个旧来源提前失效。

- 所有 Codex 展开布局及洞察页保留“重置预测与消耗计划”入口；加载、无有效来源和来源冲突均有明确文案。
- 公共信号与个人账号状态分开判断。账号数据异常时可查看公开信号，但不提供个人消耗目标。
- 暂时失败时保留仍在六小时有效期内的最后结果，标注刷新失败；不改变原时间戳，不延长有效期。缓存只在本次运行内保留。
- 展开后优先显示公开来源及其分数、数据时间、重置历史，再显示个人消耗计划。来源不足或冲突仍不显示合并概率。
- 增加独立的公开预测刷新按钮，不触发账号读取；即使暂停 Codex 账号监控，仍可手动刷新公开来源。
- 合并结果的有效时间仅取参与估计来源的最早数据时间，排除来源继续保留在详情中供核对。

本次没有更换预测模型或宣称提高预测准确率。9 月 17 日公开读取的 [Codex Reset](https://codex-reset.com/api/forecast) 返回 42 分、最近重置为 9 月 12 日；[Will Codex Reset Today](https://codexreset.app/api/signal) 返回 91 分、最近重置仍为 7 月 25 日。该时点存在明显来源分歧，因此保留各来源信息并说明冲突比恢复一个合并百分数更合适。公开响应随时间变化，不作为固定测试数据或官方未来重置承诺。

## 整体质量改进

已修复独立面板刷新失败时继续显示旧内容却没有失败提示的问题：保留画面并显示固定双语提示，恢复后清除，不直接显示底层异常内容。费用趋势及费用热力图的无障碍名称现在随 Token/费用切换。

没有现成统一质量评分量表，本轮不虚构总分。后续按收益排序：

1. 洞察导出加入统一忙碌状态、防重复提交及取消反馈；目前代码允许同时调用多个导出。
2. 为 Token/费用柱图和热力图补充键盘逐点读取；目前细节主要通过鼠标悬停查看。
3. 完成真实 Windows 多显示器、不同 DPI 和真实 Mac 操作矩阵。
4. 在稳定负载下记录启动、空闲、刷新和多独立窗口的原生资源基线，再设性能目标。
5. 优先复用现有样式和按需加载，再增加新视图：本次 CSS 为 153,325 B / 153,600 B，JavaScript gzip 为 183,386 B / 184,320 B，已接近现有预算，未放宽门槛。
