# 2026-09-12 interaction, design, and native-window follow-up

The main application improvements are described in [REVIEW-2026-09-12.md](REVIEW-2026-09-12.md). Three lower-cost agents audited functionality, request lifecycles, and chart work; a fourth independently audited the native resize failure below.

## Native clipping investigation

v0.3.12 passed the local desktop gate, eight synthetic native scenarios, and the guarded release workflow. Fresh Windows source CI then exposed failures that local persisted settings and pointer placement had not revealed:

1. The screenshot directory was absent on a fresh checkout. Test setup now creates it.
2. A dialog extended to 444px while the native viewport stayed at 268px. Waiting for resize completion did not resolve it. CI now retains screenshots, including the clipped window from run 34680024024.
3. Root cause: the expanded card's pointer-entry handler always called `expand_widget`. Native positioning could generate another pointer-entry event, resetting height to 260px plus safe insets. The DOM remained 448px tall, so its ResizeObserver did not send a new height.

The regression first failed with four native expansion calls where only two were expected. The application now requests expansion on pointer entry only when compact, while retaining refresh and collapse-cancellation behavior. Changing compact placement while pinned open resynchronizes the measured content height after the native transition. Height measurement uses `offsetHeight` to exclude entrance scaling.

The native layout scenario now also sends pointer re-entry explicitly and checks each animation frame for 350ms in both appearances. Its existing boundary/overflow assertions and two-second resize-stall timeout remain in place. These changes fix application behavior rather than hiding the failed native assertion.

## Validation and release

The corrected source passed 291 frontend tests across 39 files, production build and bundle budgets (572,734 bytes total JavaScript, 178,894 gzip, 149,233 CSS), and Rust formatting, 93 tests, check and strict Clippy. Version consistency and diff whitespace checks passed. All eight synthetic Windows native scenarios passed with the explicit pointer-re-entry assertion in both appearances; the repeated-modal frame samples ranged from 28.6 to 110.8ms on this machine. These are machine-specific samples, not a controlled comparative benchmark.

The next patch is published only after a fresh [main CI](https://github.com/silverlion2/quota-float/actions/workflows/ci.yml) passes frontend, Windows native tests/build/Defender, and macOS Universal build, followed by the guarded [release workflow](https://github.com/silverlion2/quota-float/actions/workflows/release.yml) and public-asset verification. v0.3.12 remains intact; the corrected application uses a new version. No provider credential path, account access, certificate, or signing configuration changes are involved.

Real Mac visual behavior and multi-monitor/DPI acceptance still require their corresponding hardware. Updater integrity signatures remain distinct from OS code signing and notarization.
